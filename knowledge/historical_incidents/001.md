# Historical incident: INC-HIST-001 (synthetic example)

> This is a hand-authored illustrative example for the knowledge base, not
> a record of a real past incident. It exists so the Knowledge Investigator
> agent has genuine "have we seen this before?" content to search — see
> spec §14, §49 (synthetic data only).

**Service:** checkout
**Date:** 2026-06-02
**Root cause:** database_connection_pool_exhaustion

## Summary

A deploy reduced checkout's database connection pool size as part of a
cost-reduction change. Under normal (not elevated) traffic, the smaller
pool saturated within a few minutes, and checkout's error rate rose to
roughly 40% until the deploy was rolled back.

## What worked

Rolling back the deploy resolved the incident within minutes. No pool
resize was needed — the previous pool size had been correctly sized for
the service's real traffic; the regression was purely the deploy.

## Lesson

Connection-pool size changes deserve the same scrutiny as any other
capacity change, even when framed as a "just a config value" edit.
